# Data Sheet

## Motivation
**Purpose of the data set:**

The dataset was created to support black-box optimisation (BBO) experiments for a capstone project. It contains historical queries and observed outputs for 8 functions.

**Task:**

The dataset enables training surrogate models (Random Forest and Gaussian Process) to guide the next query selection, facilitating efficient exploration and exploitation of unknown function landscapes.

**Who Provided this Dataset?**

The initial data (about 10-40 data points for each function) was provided by Imperial Business School. Subsequent data was generated by my weekly query submissions to the capstone portal

## Size and Format

**Contents:** 
* *Inputs:* For a function whose input space has dimension $d,$ each input is an element of $[0,1)^d.$
* *Outputs:* Single float value, positive or negative
* *Query format:* Hypen-separated strings rounded to 6 decimal places (e.g '0.948393-0.674839-0.474823')
* *Size of Dataset:* 279 input-output pairs that range across all 8 functions
* *Format:* txt format with floating-point values.

## Gaps in the Data

There are significant gaps in the dataset:

* **lack of spatial coverage:** In higher dimensions, it is impossible to cover the entire space given the limited initial data and limited number of queries. Furthermore, the data is clustered around promising points so some regions will naturally be unexplored
* **lack of repeated testing:** Given the limited number of queries, repeated testing is infeasible meaning there was no information about the noisiness of the functions
   

## Collection Process
* **Query generation:** Candidates points were initialised using Latin Hypercube Sampling (LHS) to fill the input space.
* **Strategy:** Fitting a Gaussian process regressor was the foundation of the query selection. During the second phase, Random Forest models were used to guide the GP

Data was collected iteratively over 13 rounds, adding new “weekly” query results sequentially to the dataset.

## Preprocessing and Uses
Minimal preprocessing was required:
* NaN columns were removed, and data types were standardized as floats.
* Inputs all came from $[0,1)$ so no normalisation was required
* Output Data was normalized implicitly by the GP during model fitting.
* No outlier removal

**Intended uses**

This data is intended for training surrogate models for BBO to model these particular functions. It is intended to demonstrate Bayesian Optimization methodology and analyse Optimisation strategies
It is a purely academic exercise and is not intended for production level ML.

**Privacy**

All functions in this BBO challenge are synthetic functions so no personal data is involved
